# Retro Route 纯前端改造需求

版本：1.0  
日期：2026-10-07  
状态：已确认的开发基线；本轮实现与验证记录见 `implementation.md`。

## 1. 产品目标

将 Retro Route 改造成可部署到 GitHub Pages 等静态托管平台的个人旅行行程工具。在电脑和手机上均可完整编辑，以地图统一呈现地点、经过顺序、交通安排、相关链接和备注，并可通过文件或二维码携带路线。

应用保留多路线管理，每条路线相互独立。浏览器负责日常保存，文件负责长期备份，二维码负责单条路线的临时跨设备传输。不同设备导入后拥有独立副本，不建立自动同步关系。

本轮重点是可靠编辑、可靠传输、可靠恢复，并延续现有复古视觉风格。地图连线为行程示意线，交通时间、距离等由用户填写，应用不自动计算道路路径或最优行程。

## 2. 已确认的范围

| 项目 | 要求 |
| --- | --- |
| 运行方式 | 纯前端，正式使用不需要 Flask、SQLite、Python、WebView 或本机服务器 |
| 托管 | 支持 GitHub Pages 项目子路径及常规静态托管 |
| 路线管理 | 保留列表、新建、切换、改名、复制、删除；路线数据相互独立 |
| 本地保存 | 浏览器自动保存全部路线和当前选择 |
| 单条文件 | 每条路线可独立导入、导出 |
| 导入规则 | 先预览；默认新增，也可明确选择替换当前路线；不合并地点或路线 |
| 全部备份 | 可导出完整路线库，并预览后整体恢复 |
| 二维码 | 单条路线生成二维码；网页内调用摄像头扫描；另支持二维码图片读取 |
| 移动端 | 完整编辑能力，保留打开外部地图导航的能力 |
| 网络 | 正常使用需要网络；不建设离线地图、PWA 或瓦片缓存 |
| UI | 复用现有配色、按钮、粗边框、硬阴影、图标和界面风格 |
| UI 文案 | 小型入口优先图标；确需可见文字时使用简短英文，不增加中文标签 |

暂不实现跨路线地点共享、地点合并、云端账号及同步、协同编辑、自动路线优化、外部地点搜索、多二维码分片、正式多日分组、跨时区计算、预算、附件和真实图片导出。用户可用多条路线组织不同旅行或不同日期。

## 3. 当前功能与问题

以下结论来自源代码检查，尚不等同于完整浏览器体验测试。

| 当前功能 | 代码入口 | 改造方向 |
| --- | --- | --- |
| 多任务与双重存储 | `src/App.jsx`、`server.py` | 保留路线管理，删除 API 双写和服务器同步 |
| 地图选点与地点库 | `src/App.jsx` | 增加地点修改，统一地点与路线节点的数据引用 |
| 路线排序 | `moveRouteItem` | 删除静默去重，保护节点和路段信息 |
| 路段时间与交通字段 | `src/App.jsx` | 保留字段；支持点击展开、真实时长和跨日表达 |
| Explore 分类与备注 | `src/App.jsx` | 修正类别选择，放宽备注，支持未加入行程的候选地点 |
| Markdown 总备注 | 预览右侧面板 | 编辑模式也提供入口 |
| 预览、主题、全屏 | `src/App.jsx` | 保留，补齐交通详情和单地点行为 |
| SNAPSHOT | 预览工具栏 | 实际仅隐藏控制栏，改为对应图标和准确提示 |
| 移动端 | `src/MobileApp.jsx` | 当前主要是演示状态，需接入共享业务逻辑 |
| 页面入口 | `src/main.jsx` | 替换 `/m` 路径判断为响应式布局，避免服务器路由依赖 |

需解决的明确问题：

- 地点添加后不能修改名称或位置，删除地点库条目不处理路线内的副本。
- 重排会静默删除相邻的相同地点。
- 分类菜单点击任意图标都循环至下一类别，而非选中点击的类别。
- 关键编辑字段仅通过鼠标悬停展开。
- 时长使用时钟规则，不能正确表达超过 23:59 的持续时间。
- 单节点时部分按钮可点击但没有结果；预览将路段数标成站点数。
- 预览缺少已录入的车站、座位、登机口等交通详情。
- 地图在部分状态更新后自动缩放，探索信息刷新依赖不完整。
- 浏览器存储读取、写入失败没有完整保护，保存状态未展示。
- 桌面和移动端地图源不同，需要核实坐标及外部导航一致性。

## 4. 核心用户流程

### 4.1 创建与编辑

打开站点 → 恢复路线库与当前路线 → 新建或选择路线 → 添加地点 → 安排节点顺序 → 编辑交通与探索信息 → 自动保存 → 预览或导航。

没有任何路线时展示同风格空状态及新建入口，不用演示地点冒充用户数据。新建会创建新的空路线并切换过去，原路线保留。

### 4.2 文件导入

选择单条路线文件 → 读取与校验 → 显示路线名称、地点数、节点数、路段数及备注摘要 → 选择 `Add` 或 `Replace` → 确认 → 更新本地路线库。

默认 `Add`；没有当前路线时不提供 `Replace`。替换前清楚标明目标路线，可先导出目标路线；不强制导出。取消或校验失败均不改变数据。

### 4.3 二维码传输

发送端选择路线 → 生成压缩二维码 → 接收端打开站点并点击扫描 → 申请摄像头权限 → 识别、校验 → 展示与文件导入相同的预览 → 确认导入。

接收端也可选择二维码图片，复用同一解析与导入流程。无需把路线放进 URL，不支持通过系统相机自动打开导入链接。

### 4.4 完整备份与恢复

导出全部路线 → 下载路线库备份文件。恢复时读取备份 → 显示路线清单、数量及整体替换说明 → 确认后整体替换本地路线库。

单条路线导入和路线库恢复必须在界面上区分。路线库恢复不提供合并，不逐条提交；任何一条数据校验失败时不部分覆盖。

## 5. 功能需求

### 5.1 路线库

- 每条路线拥有独立标识、名称、地点、节点、路段、探索信息和总备注。
- 路线抽屉复用现有结构，显示名称、地点／节点数量，支持新建、切换、改名、复制、删除和单条导出。
- 当前路线明显标识；编辑未完成的字段不会因切换路线丢失。
- 复制生成新的路线标识，内容相互独立；修改副本不影响原路线。
- 删除后可撤销；删除当前路线后选择一条剩余路线，没有剩余路线则进入空状态。
- 不因路线名称相同而覆盖数据。导入同名路线时在预览说明，新增后可改名。
- 文件操作通过独立入口提供单条导入、单条导出、全部备份、恢复、二维码生成及读取。

### 5.2 地点库

- 地图点击添加地点，录入名称；保留原始大小写，不强制转换为大写。
- 可修改名称，并通过重新选点修改位置；同时支持坐标输入与校验。
- 地点有直接的加入路线、地图定位、编辑、导航和删除入口。
- 添加操作应有明确的开启／取消状态，避免浏览地图时持续误建地点。
- 删除被路线使用的地点时说明受影响的节点数，确认后同时删除这些节点及失效路段信息；取消则全部保留。
- 支持按已保存的名称筛选，显示空结果，清除筛选后恢复完整列表；不调用外部地名搜索。
- 地点修改同步反映到所有引用它的节点及地图标签。
- 地点可保存 Explore 类别、外部链接和多行备注，即使没有加入路线也可查看。
- 取消当前 28 字符备注限制；长内容在列表中摘要显示，在详情中完整查看。统一输入上限与导入上限，具体数值在实现时确定。

### 5.3 路线节点与排序

- 每次经过一个地点形成独立节点；允许多次经过同一地点，包括连续重复。
- 保留上下移动；移动端触摸操作与桌面键盘操作均可使用，不依赖拖拽。
- 连续同地点可提示，不自动删除。
- 移除节点不删除地点库条目。
- 路段以相邻节点的有向关系识别。排序后仍存在的相邻关系保留信息，新关系为空；不把旧路段详情自动套到新关系。
- 失效路段不参与显示、计算、文件或二维码导出；撤销可恢复重排前的信息。

### 5.4 路段与时间

- 交通方式直接选择 `Car`、`Train`、`Flight`、`Walk`，图标展示当前值。
- 路段点击展开／收起，不依赖 hover 才能操作。展开后显示时间及对应的专属字段。
- 保留铁路出发／途经／到达站、飞机座位／登机口、步行距离及估算步数。
- 距离必须为有效的非负数；步数显示为估算值，不宣称实际步数。
- 出发、到达使用当地时钟；时长使用非负总分钟或等价小时＋分钟，支持超过一天。
- 修改出发时，优先用已有时长推算到达；没有时长而有到达时则推算时长。
- 修改时长时，优先用已有出发推算到达；没有出发而有到达时则反推出发。
- 修改到达时，优先保持已有出发并推算时长；没有出发而有时长时则反推出发。
- 到达支持显式相对日偏移；显示 `+1d` 等提示，避免多日时长被折回成零点附近。
- 没有日偏移的旧数据可按最短非负间隔推断跨午夜；预览提示这是推断结果，用户可调整。
- 不自动修改其他路段的时间。可提示相邻路段冲突，不因不完整信息阻止保存。
- 空值与输入中的半成品可以编辑和保存草稿；无效时间不能进入计算，预览给出未完成标识。
- 第一版不支持完整日期、时区转换或自动交通查询。

### 5.5 Explore 与总备注

- 保留住宿、餐饮、自然、购物、摄影、收藏类别；选择图标后立即变为对应类别。
- 地图和列表更新及时，不要求切换模式后刷新。
- 点击地点查看信息；hover 可作为桌面辅助反馈。
- 外部链接仅在用户主动操作时打开；校验可接受的链接协议，不自动执行导入内容。
- Markdown 总备注在编辑和预览中均可访问，支持编辑／查看切换。

### 5.6 地图、预览和导航

- 桌面和移动端共享地图数据与坐标处理。地图源的选择、坐标转换与外部导航通过实际地点验证后确定。
- 提供放大、缩小、查看全部路线及定位选中地点入口；可选的设备定位不作为核心流程前提。
- 自动适配视野发生在载入、切换路线或用户点击适配时；编辑文字、主题或备注不打断用户当前地图视野。
- 恢复地图来源署名；必要标注融入现有视觉布局。
- `Routing` 与 `Explore` 分别选择目标模式，点击已选中的模式不反向切换。
- `Execute` 保留作为查看／编辑交通安排的入口，不播放模拟计算动画或暗示自动规划。
- 零节点时提供清楚的空状态；一个节点可预览、查看 Explore 及导航，交通面板说明没有路段。
- 预览显示路线名称、准确数量、时间及可展开的交通详情、Explore 和总备注。
- 全屏是独立操作，进入预览不强制全屏；不支持全屏时仍可正常预览。
- 隐藏控制栏功能采用图标及 `Hide Controls` 提示，点击或触摸可恢复，不生成截图。
- 地点或选定的地图位置提供 `Navigate` 图标按钮，不再通过放大后点击任意位置直接跳走。
- 延续 Apple Maps／Google Maps 的设备适配方向；外部链接可能打开 App 或网页，由设备决定。传递交通方式以目标服务实际支持为准。
- 跳转前保留编辑状态，返回网页仍可继续使用。
- 瓦片失败时显示简短状态与重试入口，不覆盖路线或阻止文本编辑、导出。

### 5.7 保存、撤销及多标签页

- 以浏览器本地存储保存路线库；初版优先使用 `localStorage`，封装存储接口以便后续替换。
- 明确显示 `Saved`、`Saving`、`Save Failed` 及可查看的保存时间；不能将失败标成成功。
- 读取数据损坏时不立即写空数据覆盖原值，提供恢复或导出可保留内容的路径。
- 存储不可用或容量不足时保留内存内容，允许文件导出，并明确本次编辑尚未持久化。
- 输入变化可短暂防抖写入；路线切换和可捕获的页面隐藏／离开事件提交待写内容。
- 提供撤销／重做，覆盖地点修改／删除、节点增删／排序、字段编辑、路线删除及导入替换。连续文本输入合并为一次合理编辑。
- 操作历史为有限的会话内历史，不要求随文件导出或刷新后恢复；具体容量在实现时确定。
- 撤销状态不以多条历史路线形式出现在任务列表，不恢复旧后端同步。
- 同一站点多个标签页用存储变更事件与修订号检测更新。无本地待保存变更时可同步刷新；发生冲突时暂停覆盖，提供载入已保存版本或先导出本页内容的选择。

### 5.8 文件与二维码

- 单条文件建议扩展名 `.retro-route.json`；全部备份建议 `.retro-route-backup.json`，均为 UTF-8 JSON。
- 文件名包含安全处理后的路线名和时间；不覆盖操作系统中的已有文件，由浏览器下载机制处理。
- 单条文件保存完整有效路线数据，不包含其他路线或接收设备的 UI 偏好。
- 备份保存全部路线、当前路线引用及恢复所需元数据；恢复不修改接收设备的主题偏好。
- 文件和二维码共用校验、迁移、预览及确认逻辑。
- 新增导入生成新的本地路线标识；替换保留被替换路线的本地身份。文件内标识不能触发无提示覆盖。
- 校验格式、版本、字段类型、有限数值坐标、唯一标识、节点引用、路段关系、类别和数据大小。
- 合法但未完成的编辑字段允许导入；结构破损的数据不导入。未来不支持的版本明确报错。
- 地点名称、备注等视为文本，地图弹窗不直接插入未转义的 HTML。
- 设置文件大小、解压后大小及条目数量上限，避免损坏输入使界面卡死；限制与提示在实现时根据样例确定。
- 二维码采用带版本前缀的压缩协议，例如 `RR1:`；前缀、压缩和编码方法固定并测试双向兼容。
- 扫描与解码在浏览器完成；路线内容和摄像头帧不上传。地图瓦片、字体及用户主动打开的外部链接仍可能产生网络请求。
- 仅在用户点击扫描时请求摄像头，优先后置摄像头；退出扫描、识别成功或页面隐藏时停止摄像头。
- 权限拒绝、无摄像头、识别失败、不支持的环境均提供英文提示及文件／图片导入路径。
- 二维码用纯黑白、足够尺寸和留白，不套地图滤镜、纹理、动画或装饰图标。
- 容量判断基于实际压缩结果、纠错等级和实测识别效果，不承诺所有路线均可装进单码。
- 超限时提示改用文件，不自动截断备注、丢弃地点或降低数据完整性。

## 6. 数据模型与迁移原则

采用独立的路线文档与路线库模型，UI 不直接依赖历史 Flask 响应结构。以下为约束性设计，最终字段名在开发前固定。

| 对象 | 内容 |
| --- | --- |
| 路线文档 | 标识、名称、创建／修改时间、地点集合、节点序列、路段详情、Markdown 总备注 |
| 地点 | 稳定地点标识、名称、坐标及坐标体系、Explore 类别／链接／备注 |
| 路线节点 | 稳定节点标识、地点引用；不重复存储地点名称和坐标 |
| 路段 | 前后节点引用、交通方式、时间／相对日偏移、时长和交通专属字段 |
| 本地路线库 | 存储版本、全部文档、当前选择、修订号与写入时间 |
| UI 偏好 | 深色主题等设备设置，与路线文档分开 |
| 单条文件 | `format`、`version`、导出时间和一份路线文档 |
| 备份文件 | 独立 `format`、`version`、导出时间、全部文档及当前选择 |

文件格式与本地存储格式分别标记版本。不可把接收设备的主题、面板状态和撤销历史作为路线内容传输。

旧数据迁移要求：

1. 在退役后端前，提供一次性导出 SQLite 中全部任务的方式；不将数据库发布到静态站点。
2. 将 `task_name` 和 `task_data` 映射为路线文档，保留名称、节点顺序、重复访问和全部交通专属字段。
3. 将旧 `locationsDb` 和 `route` 转换为地点引用；路线中的地点如果不在旧地点库中，补回地点后再转换。
4. 旧副本存在名称或坐标冲突时不静默改写，保留原始备份并生成迁移说明。
5. 旧 `segmentDetails` 依赖节点 ID，迁移时建立对应关系；无法映射的历史记录保留在原始备份及迁移说明中，不当作有效路段。
6. 迁移旧 Explore 信息及总备注，分离旧 `isDarkMode`；无业务用途的历史字段不进入新文档。
7. 支持旧浏览器同来源的任务缓存迁移，成功校验并保存后仍保留旧键供恢复，不提前清除。
8. 部署到新域名／端口时不能自动读取原来源缓存；用文件完成跨来源迁移。

迁移工具属于开发／升级辅助，不让正式应用继续依赖 SQLite 或 Flask。

## 7. 界面与视觉规范

沿用当前视觉体系，不以新的通用 UI 套件替换主体设计。

| 元素 | 规范 |
| --- | --- |
| 浅色背景 | `#EBE5D9`，内部面板沿用 `#F7F4EE`／白色 |
| 文字与边框 | 炭黑 `#2C2A29` |
| 强调色 | 橙红 `#D95D39`，突出主要动作和选中状态 |
| 深色主题 | 沿用 `#111111`、`#1A1A1A`、`#222222`／`#2A2A2A` 与橙红边框 |
| 形状 | 方角、粗边框、硬阴影；保留按钮按压位移 |
| 字体与图标 | 等宽字体及现有 Lucide 图标体系，保留终端与编号标题风格 |
| 小型操作 | 新建、编辑、复制、删除、导入、导出、扫描、定位等优先图标 |
| 可见文字 | 必要标签用英文，如 `Routing`、`Explore`、`Execute`、`Preview`、`Add`、`Replace` |
| 图标说明 | 桌面 hover／键盘焦点显示简短英文 tooltip；移动端不能只靠 hover 理解操作 |
| 可访问性 | 图标按钮有英文可访问名称，选中／禁用状态明确；焦点可见，弹窗可关闭并管理焦点 |
| 触摸 | 小图标可保留尺寸，但触摸区域建议至少 44×44 CSS px，避免相邻误触 |
| 异常与确认 | 英文短句说明问题和影响范围，不能只用颜色或图标表达覆盖、错误和保存失败 |

图标优先不意味着所有界面禁止文字。路线名称、地点名称、用户备注保留用户输入的语言；应用自身标签、提示、帮助和错误使用英文，不加入中文 UI 标签。本文仍以中文作为需求说明。

桌面保留路线抽屉及地点／节点侧栏、地图主体；中小屏改为可折叠面板或底部抽屉。底部保留主要模式操作，次要文件入口集中在路线／文件菜单。移动端支持长名称、键盘弹出、安全区域及横竖屏切换，不出现横向溢出。

共用主题色、按钮、图标按钮、面板、弹窗、字段、提示组件，避免新增功能出现另一套视觉样式。hover 只作辅助；尊重减少动画设置，关键反馈不依赖闪烁动画。

## 8. 技术与部署约束

- 保留 React、Vite、Leaflet、Tailwind 和现有图标／Markdown 基础，按职责拆分巨型组件。
- 共享文档状态、编辑操作、存储、校验、文件和二维码协议；桌面／移动仅布局和交互呈现不同。
- 建议拆分 `domain`、`storage`、`transfer`、`map`、共享 UI 及布局模块；具体文件树在实现时确定。
- 响应式入口支持子路径；不依赖 Flask catch-all、`/m` 或服务器端重写。
- 构建资源、图标和页面引用支持部署 base；站点根路径及项目子路径均需验证。
- 正式应用没有 `/api/tasks`、`:5001` 或后台同步请求，无需后端环境变量。
- 只部署构建产物，不发布 `.env`、SQLite、用户路线、迁移备份或 Python 控制台。
- 摄像头要求部署环境满足浏览器安全上下文；二维码解码具备兼容方案，不仅依赖原生 `BarcodeDetector`。
- 地图源及外部导航的使用方式在实现前核实，保留必要来源标注。
- 生成和扫描按需加载，控制初始包体；扫描循环有适当频率，不持续阻塞编辑。
- 文本显示与外部链接校验覆盖文件、二维码及旧数据迁移路径。

## 9. 实施顺序

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| 1 | 固定文档格式、地图坐标策略及旧数据迁移 | 现有路线能够无损迁移，并保留原始备份 |
| 2 | 共享编辑层、本地多路线库、保存与历史操作 | 不启动后端也能在桌面编辑、切换、刷新恢复 |
| 3 | 文件导入导出、全部备份与恢复 | 单条及全部数据经往返转换后内容一致 |
| 4 | 移动完整编辑、地图／预览／导航、易用性修正 | 两端共享同一业务行为，实际导航位置一致 |
| 5 | 二维码生成、相机与图片读取 | 两端扫码往返，失败时不修改原数据 |
| 6 | 视觉统一、静态部署及端到端验收 | GitHub Pages 等静态环境通过完整流程验证 |

本文为需求基线。当前已实施纯前端改造；正式部署和真实移动设备验证由用户完成，旧后端文件暂留作迁移与参考，不参与正式应用运行。

## 10. 验收标准

### 10.1 核心数据往返

1. 不启动 Python 或 Flask，创建两条路线，每条分别录入地点、重复节点、路段时间、不同交通字段、Explore 与中文／英文 Markdown 内容。
2. 切换并刷新，两条路线均恢复且互不影响。
3. 单条导出并在另一浏览器导入；预览数量正确，取消不改变数据，`Add` 保留原路线，`Replace` 仅替换选中路线。
4. 复制、改名、删除、撤销／重做后，其他路线内容不变。
5. 全部备份并恢复，路线库及当前选择正确；损坏备份不部分恢复。
6. 手机扫码导入、修改并导出文件，电脑再导入，业务字段和地图位置保持一致。
7. 测试超过 24 小时时长、跨午夜、同地点多次经过、排序后路段变化，计算与数据保留符合定义。

### 10.2 编辑与视觉

- 两端都能编辑所有字段，不能存在只有 hover 才能使用的功能。
- 修改地点后所有引用一致；删除影响明确；重排不静默丢节点。
- 预览完整展示交通详情，空路线、单节点、长名称、多行备注均正常。
- 新增菜单、对话框和小按钮遵循本文件视觉规范；必要 UI 文案为英文。
- 触摸区域、键盘焦点、弹窗退出、软键盘和横竖屏经过验证。

### 10.3 异常、部署及兼容

- 存储禁用／满额、损坏缓存、错误文件、不支持的版本、二维码超限、解压异常、权限拒绝、地图失败均有可理解的英文反馈；原数据不会被错误覆盖。
- 两个同来源标签页同时编辑时能检测修订冲突，不静默覆盖另一页的数据。
- 退出或完成扫描后摄像头关闭。
- 现有数据库样例及旧缓存样例迁移验证通过。
- 正式构建和 lint 通过；业务测试重点覆盖时间、排序引用、导入原子性、迁移和二维码往返。
- 在静态预览及项目子路径部署验证资源路径、刷新、相机和导入导出，不发出旧后端请求。
- 桌面浏览器、iOS Safari 和 Android Chrome 作为主要验证对象；相机、文件下载和外部地图跳转需要真实移动设备验证，无法验证的环境须在交付中明确记录。
