# 部署后设备测试清单

本地浏览器自动化使用 Chromium 和窄屏布局，真实移动设备由用户部署后验证。

## 第一轮建议

1. 电脑创建两条路线，分别添加至少两个地点。测试改名、复制、切换、刷新恢复。
2. 路线 A 添加 `Hotel → Station → Hotel`，改名 Hotel，确认两处一起更新。重排成相邻 Hotel，确认没有被静默删除。
3. Execute 点击路段卡片，填写出发 `23:30`、时长 `25:45`，到达应是 `01:15 +2d`。切换 Train／Flight／Walk 并填专属字段。
   手机上也可直接输入 `2330` 和 `2545`，离开输入框后应分别整理成 `23:30` 和 `25:45`。
4. 添加 Explore 链接、多行备注和 Markdown 总备注，手机确认完整可编辑。
5. 桌面单条导出，手机文件导入后先取消，确认没有变化；再次导入 Add，再测试 Replace 仅替换目标路线。
6. 电脑显示二维码，手机网页扫描。测试拒绝权限的提示、重新开启、关闭后相机指示器熄灭。
7. 将二维码保存到手机照片／文件中，使用 QR 图片入口识别；无需另一台设备。
8. 手机修改路线并导出文件，电脑重新导入，检查所有字段和地图位置。
9. 从地点和路段打开系统地图，核对目标位置；返回网页确认编辑数据仍在。
10. Export full library，再 Restore All；注意恢复会替换所有路线。测试取消和撤销。

## 界面

- 小图标按钮是否容易点，名称很长时是否溢出。
- 手机横竖屏、键盘弹出、弹窗滚动、底部安全区域是否正常。
- Sequence 标签下可以使用 Execute 和 Preview；Locations 标签下可以选点和编辑。
- 深色／浅色地图标注是否可读，署名是否被遮住。
- 导出文件是否进入预期下载位置；iOS 的分享／预览行为由浏览器决定。
- 长路线二维码超限是否清楚提示导出文件，而不是丢弃字段。

## 存储与旧数据

- 同站点两标签页编辑，观察另一页更新与冲突提示；发生冲突时先导出本页，再 Load Saved。
- 私密浏览或禁用存储时，查看 Save Failed，并确认内存内容仍能导出。
- 导入迁移文件后，选择正确坐标源并核对几个实际地点；转换默认假设旧桌面数据来自高德。
- 新旧站点地址不同不会共享浏览器缓存；使用文件迁移。

反馈建议记录设备／系统、浏览器、触发步骤、期望与实际结果。避免在公开反馈中上传含私人行程的文件。
